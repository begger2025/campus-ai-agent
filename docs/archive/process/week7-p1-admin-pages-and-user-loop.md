## P1b 用户体系

后端（TDD，`backend/tests/test_user_management.py` 15 个用例）：
- `POST /api/auth/register`：公开注册。用户名 3-32 位字母/数字/下划线/短横线、
  密码≥8 位（Pydantic 422）；重名 409；**角色不接受请求方指定**，一律 user（防提权）；
  成功即返回 token 自动登录。
- `GET /api/admin/users`：分页 + 用户名/昵称关键词 + 角色/状态筛选，不返回密码哈希。
- `PATCH /api/admin/users/{id}/status`：active/disabled；**不能禁用自己**；禁用后
  登录立即 403；写操作审计日志。

前端：登录页"注册账号"对话框（校验+注册即登录）；运维中心"用户管理"页签
（禁用需二次确认；可用来清理 wp8/wp9/wp10/smoke 等历史验收测试号）。

## P1c 前台闭环（消灭假逻辑）

- **反馈入库**：EventFeedbackDialog 真实调用 `POST /api/feedback`
  （target=public_event#id，登录用户带用户名），管理员在运维中心处理。
- **事件详情**：改调 `GET /api/events/{id}` 详情接口（带 representative_posts），
  兼容 `9`/`EVT-9` 两种 ID；加载失败展示错误而非假数据。
- **舆情工作台去假**：删除 setTimeout 假"开始分析/Agent 问答"；关键词/来源改为
  本地筛选真实事件；右栏改为舆情助手引导（按所选事件生成建议问题，
  `?q=` 跳转预填、不自动发送）。
- **游客浏览**：首页/事件列表/事件详情 `meta.public` 免登录（与登录页宣传一致），
  顶栏游客显示"登录"按钮；工作台/助手/后台仍需登录。

## 浏览器手动验收清单（dev.bat 或 run.bat 后过一遍）

1. 未登录直接开 `/events` → 能看事件列表，顶栏是"登录"按钮；点详情能看代表帖。
2. 登录页"注册账号" → 新用户名注册 → 自动登录落在 `/opinion`。
3. `admin/admin123456` 登录 → 落在 `/admin`，六张 KPI 卡有真实数字。
4. `/admin/events` → 挑一条 draft 通过（或驳回，驳回必须填原因）→ "历史"抽屉出现
   这条记录 → 前台事件列表可见（通过时）。
5. `/admin/raw-posts` → 按平台"小红书"筛选 → 打开一条详情抽屉 → 点"打开原帖"。
6. `/admin/ops` → 反馈页签处理一条反馈；用户管理页签禁用 wp8_user → 用它登录
   应提示"该账号已被禁用" → 重新启用。
7. 工作台 `/opinion` → 关键词筛选事件 → 右栏点建议问题 → 跳到舆情助手且输入框
   已预填 → 发送得到真实回答。
8. 事件列表点"反馈" → 提交 → `/admin/ops` 反馈页签能看到这条新反馈。
