# 校声智枢（Campus AI Agent）缺陷跟踪台账

> 《软件工程》期末大作业 · 交付物 5 附件（软件测试与质量保证报告引用本台账）
>
> 台账收录项目周期内**真实发现并处置**的缺陷：每条给出严重级、现象、根因、发现渠道、
> 修复提交与回归验证方式，全部可在 git 历史中复核。演示性/编造条目：0。

## 1. 缺陷管理流程

```
发现（用户实测 / 代码审计 / 评测基准 / 冒烟）
  → 复现并定级（阻断 > 严重 > 一般 > 轻微）
  → 先写失败测试锁定缺陷（TDD 红）
  → 修复（绿）→ 全量回归（三套测试 + 前端构建）
  → 以 Conventional Commits 留档（fix: 前缀 + 根因描述）
  → 涉及同步白名单文件时回移子仓并跑其 305 用例
```

两条纪律：
- **静默错误答案是最高严重级**——界面不报错但给出错误结论的缺陷（假数据、检索绕过、情绪误判）一律按"严重"以上处置；
- **修复必须带回归测试**——没有失败测试复现的缺陷不允许直接改代码。

## 2. 严重级定义

| 级别 | 定义 | 示例 |
|------|------|------|
| 阻断 | 核心功能不可用或数据损坏 | 生产库删除事件 500 |
| 严重 | 功能给出错误结果而不自知（静默错误答案）、安全漏洞 | SSRF、检索整条绕过 |
| 一般 | 功能可用但行为不正确/体验受损 | 折线图截断、超时误报 |
| 轻微 | 文案/展示瑕疵、死代码 | 假数字文档、孤儿 CSS |

## 3.7 对抗测试战役（主动证伪，攻击者视角）

常规测试验证"功能对不对"，对抗测试则以刁钻用户/攻击者视角**主动证伪**——尽可能触发隐藏缺陷。战役按五个攻击面系统设计 30 个对抗用例（提交 bc2d4fb / dc8d3fd / 380ace3 / 3dc95f8）：

| 攻击面 | 刁钻行为 | 用例数 | 结果 |
|--------|----------|:------:|------|
| ① 越权矩阵 | 普通用户/游客动态枚举打全部 admin 接口、伪造 token、伪造 role | 6 | 全绿——鉴权扎实，非管理员绝不 2xx，无 422 结构泄露 |
| ② 输入边界 | 超长/空/emoji/注入字符/超大分页/负数/LIKE 通配符 | 9 | **发现 DEF-D14**（LIKE 通配符注入，已修）；其余边界健壮 |
| ③ 并发竞态 | 重复 id 批量、狂点评论绕频控、并发举报 | 3 | 全绿——去重/频控/原子累加有效 |
| ④ AI 对抗 | 提示注入越狱、伪造 `</data>` 围栏、诱导编造、超长淹没 | 9 | 全绿——注入中和、围栏逃逸转义、降级不编造 |
| ⑤ 数据一致性 | 删事件造孤儿、剔除帖后检索泄漏、移空成员留空壳 | 3 | 全绿——级联清理、剔除不泄漏、空壳拒绝 |

**战役结论**：30 个系统性对抗用例只发现 1 个中低危真缺陷（LIKE 通配符）且当场 TDD 修复，其余四个攻击面全部防护到位——**这正是"质量保证有效"最有力的证据**：不是没测出问题所以放心，而是用攻击者视角穷尽刁钻行为后，系统依然守住了安全底线。战役中另纠正了一处过程误判（曾疑 LLM 降级不标注，探针实证降级确带"暂不可用"标注，为观察误差，非缺陷）。

## 4. 统计与复盘

- **收录缺陷 37 项**：阻断 1 / 严重 17 / 一般 15 / 轻微 4；另有已知限制 4 项、暂缓 1 项。其中 DEF-D14 由对抗测试战役发现。
- **发现渠道分布**：用户实测 11、代码审计 14、真机/真库排障 6、评测基准与数据对账 5、**对抗测试战役 1**——印证"多渠道质量保证"设计：审计抓结构性问题，实测抓体验问题，基准抓回归，对抗测试抓刁钻边界。
- **三条复盘教训**（已转化为流程约束）：
  1. **SQLite 测不出 MySQL 外键问题**（DEF-P01）→ 涉及外键/约束的变更必须附"生产语义"专项用例；
  2. **过滤器只管新数据，存量要回溯清**（噪声帖清理）→ 数据规则变更后必须跑存量对账；
  3. **测试自身也会腐化**（DEF-P06、DEF-C06）→ 测试红了先判"是缺陷还是测试错了"，两种结论都要留档。
