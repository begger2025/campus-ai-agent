## 0. 录制前准备清单（务必逐项确认）

### 0.1 环境与账号

- [ ] 公网站点可访问（<http://8.134.250.107:9000>），或本地 `run.bat` 启动后用 `http://localhost:9000`；
- [ ] 演示账号可登录：普通用户 `user` / `user123456`，管理员 `admin` / `admin123456`；
- [ ] 库里有**已发布事件**（游客/首页要能看到内容）、有 **draft 事件**（审核演示要有料）；
- [ ] 清理测试验收账号（wp8/wp9/smoke），登录页/用户列表别露出它们；
- [ ] LLM 三组 key 已配（对话/预审要真调），备胎链已配（演示容灾）。

### 0.2 ⚠️ 对话延迟的应对（决定视频质量）

对话助手 P50 约 14 秒——**直播干等是大忌**。三选一：

1. **预热缓存（推荐）**：录制前先把演示要问的问题**问一遍**（temperature=0 + 缓存，第二次秒回），录制时问同样的问题即命中缓存、瞬间出字；
2. **剪辑加速**：如实录制，后期把等待段 2~4 倍速，配一句字幕"（AI 多步推理中，已加速）"；
3. **流式演示**：用流式接口，强调"2.7 秒开始出字"的体感（虽然总耗时一样）。

> 首选方案 1。既真实（就是系统缓存能力）又流畅。切忌方案外的"假装打字"。

### 0.3 录制设置

- [ ] 分辨率 1920×1080，浏览器缩放 100%，全屏无关标签页关掉；
- [ ] 录屏工具：OBS / PowerPoint 录屏 / 剪映；开麦克风或后期配音；
- [ ] 网络稳定（连公网站点时）；关掉可能弹窗的通知；
- [ ] 准备好旁白稿（下方每镜头的"旁白"可直接念）。

## 1. 视频结构总览

```
片头(15s) → 一、项目概述与架构(60s) → 二、游客/普通用户视角(90s)
→ 三、AI 核心：对话助手(120s) → 四、AI 核心：事件聚类与研判(90s)
→ 五、管理后台与 AI 预审(90s) → 六、证据核验与容灾(60s)
→ 七、工程化亮点(60s) → 片尾(15s)
```

设计原则：**AI 深度融合是主线**（三、四、五、六都在讲 AI），前面铺垫、后面升华，让评审全程感受到"这不是普通 CRUD 系统"。

## 3. 拍摄注意事项汇总

| 类别 | 要点 |
|------|------|
| **延迟** | 对话/预审提前预热缓存或后期加速，绝不干等；字幕注明"已加速" |
| **真实性** | 全程真实操作真实数据，不摆拍假页面；出错就重录别用假图 |
| **隐私** | 别录出 .env、API key、真实数据库密码、测试账号；地址栏 IP 可保留（部署址本就要给老师） |
| **节奏** | 讲解性镜头（架构/聚类原理）配图别停超 15 秒；操作镜头手速稍慢让人跟上 |
| **旁白** | 用上面每镜头的旁白稿，语速适中；专业名词（意图路由/消融/SSRF）说出来但别展开 |
| **重点** | 三、四、五三段是 AI 核心，时间给足；CRUD 类（列表/表单）快速划过 |
| **收尾** | 每段结束留 1 秒静帧，方便剪辑 |
