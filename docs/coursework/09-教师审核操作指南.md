## 1. 这个系统是做什么的（30 秒了解）

校声智枢是一个**校园舆情感知与智能分析平台**：它从微博、贴吧、知乎、快手、小红书五个平台
自动采集校园相关讨论，用 AI 把散落的帖子**聚合成"事件"**、研判每个事件的**风险等级**，
并支持用**自然语言对话**追问舆情、**联网核查**信息真伪。学生可以浏览、提问、投稿、评论，
管理员负责审核发布与运营。

一句话：**多平台采集 → AI 聚类成事件 → AI 研判风险 → 人工审核发布 → 对话式追问**。

## 2. 推荐审核动线（跟着做，约 15 分钟）

### 第一站 · 游客视角（不用登录，1 分钟）

1. 打开 http://8.134.250.107:9000 ，进入登录页后，点登录框下方的**"游客浏览公开事件"**按钮；
   - ⚠️ **如果打开网址后没进登录页、而是直接进了首页**，说明这台浏览器**记住了上一次的登录状态**。
     此时先点右上角头像 → **"退出登录"**，回到登录页即可看到游客入口；或改用浏览器的**无痕/隐私窗口**打开，
     就是干净的游客态（详见 §5）。
2. 进入**事件列表**——这些是 AI 聚合、管理员审核发布过的舆情事件；
3. **随便点开一个事件**，查看它的摘要、风险标签、以及支撑它的原始帖子。

> **看点**：游客无需注册就能看已发布事件，体现"面向公众的透明度"；而未审核的原始数据、
> 后台功能对游客不可见——**权限边界清晰**。

### 第二站 · 普通用户视角（用 user 登录，6 分钟）

回到登录页，用 `user` / `user123456` 登录，登录后自动进入**首页仪表盘**。左侧菜单从上到下体验：

| 顺序 | 页面 | 怎么用 / 看什么 |
|------|------|----------------|
| ① | **首页** | 看顶部四个统计卡（已发布事件/高风险/最近新增/采集帖子）、近 30 天发帖趋势折线、态势结构（风险分层 + 帖子情绪 + 来源平台）。**趋势图鼠标悬停**在折线上可看每天具体数值 |
| ② | **舆情分析** | 从**帖子层面**看数据：情绪分布、五平台来源占比、发帖趋势、热度榜。可用顶部搜索框按关键词/平台筛选帖子 |
| ③ | **舆情助手** ⭐ | **本项目最大亮点**，见下方"重点体验" |
| ④ | **事件列表** | 检索全部已发布事件，可按风险等级筛选，点"研判"进工作台 |
| ⑤ | **舆情工作台** | 选一个事件，看 AI 给出的**研判依据**：风险怎么判的、事件处于什么阶段、优先级怎么算的、代表帖是哪些（可点回原帖）|
| ⑥ | **舆情关注** | 中高风险事件的处置队列，按优先级排序 |
| ⑦ | **我要投稿** | 学生提交校园线索（文字+图片），审核通过后进入数据管线。可在此页查"我的投稿"进度 |

#### ⭐ 重点体验：舆情助手（对话式问答）

进入"舆情助手"页，**依次输入下面几个问题**（可直接复制），感受 AI 能力：

1. 输入 **`最近有什么热点？`** → 秒回 + 逐字流式输出；
2. 输入 **`饭堂涨价有什么讨论？`** → 即使库里帖子写的是"食堂"，也能**语义检索**命中（不是简单的关键词匹配）；
3. 接着追问 **`那有什么风险吗？`**（故意不说主语）→ 它**记得**上一轮在聊食堂，直接接着答；
4. 输入 **`给我一份宿舍搬迁舆情简报`** → 生成的简报里有 **[1][2] 蓝色角标**，**点击角标可跳转到信息来源**（原帖或事件），底部还有"参考来源"清单；
5. 输入 **`帮我写一段代码`**（越界问题）→ 它会礼貌地把话题引导回校园舆情，不乱答。

> **看点**：回答**可溯源**（每个结论都能点角标查出处，AI 不能凭空编造）、**多轮记忆**、
> **语义理解**（懂近义改写）、**有边界**（不跑题）。这是"AI 深度融合"的集中体现。

### 第三站 · 管理员视角（用 admin 登录，8 分钟）

点右上角**"退出"**，改用 `admin` / `admin123456` 登录。左侧菜单会多出"后台管理"整组。重点看这几个：

| 页面 | 怎么用 / 看什么 |
|------|----------------|
| **后台概览** | 今日工作台 + 数据管线各环节的健康度与数量 |
| **事件审核** ⭐ | 审核核心页，见下方"重点体验" |
| **数据管理** | 浏览全部采集帖子，可按平台筛选；对无关帖子可**剔除**（要填理由，可恢复） |
| **智能选题** | AI 根据用户提问等信号，**推荐下一轮该采集哪些关键词**——体现"AI 参与数据工程" |
| **证据采集** | 针对存疑事件发起**联网检索**，AI 检索权威来源、人工审核后入库（真伪核查通道）|
| **投稿审核** | 处理学生投稿：通过（进数据管线）或驳回（填理由）|
| **评论管控** | 复核被举报的评论，可隐藏/恢复 |
| **运维中心** | 反馈处理、采集任务记录、系统与操作日志（可追责）|

#### ⭐ 重点体验：事件审核

1. 进"事件审核"页，打开右上角**"审核优先排序"**开关 → 列表会把高风险、热门的事件排到前面；
2. **勾选几条**待审核（draft）事件 → 点**"AI 预审建议"**按钮 → AI 会给出"建议发布/驳回 + 一句话理由"；
3. 参考建议后，用**"批量通过"或"批量驳回"**处理（每次操作都会记审计日志）；
4. **点开任意一条事件**，在右侧抽屉里可以**改名、合并近重事件、增删成员帖**——这是"人工修正"，
   改过的事件会打上**"人工修正"徽章**，之后系统自动流程**不会覆盖**您的修改。

> **看点**：**AI 只建议、发布权始终在人**。AI 把审核的单次成本降下来（排序 + 预审摘要 + 批量），
> 但最终决定由管理员做——这是有意保留的人工闸门，符合"宁可慢、不可错发"的原则。

## 3. 五个必看亮点（答辩重点，建议逐一确认）

1. **对话可溯源**：舆情助手的每个结论都带可点击的引用角标，点开能查到具体来源帖，
   杜绝 AI 胡编（"给我一份宿舍搬迁舆情简报"最能体现）。
2. **语义聚类成事件**：几百条散帖被 AI 自动聚成有意义的事件并研判风险，不是人工整理的。
3. **AI 建议 + 人工裁决**：事件审核页的"AI 预审建议"与"人工修正"闭环——机器提效、人做主。
4. **多通道感知**：既有关键词搜索（捞学生声音）、又有联网证据核查（核官方信息）、
   还有官方账号订阅（盯校方发声），信息来源立体。
5. **断网也能用**：所有 AI 环节都有"规则兜底"，即使大模型临时不可用，系统功能依然完整
   （只是回答会简化并显示降级提示）——这是可靠性设计，不是故障。

## 5. 可能遇到的情况与解决办法（重要，请先读）

| 现象 | 是否正常 | 说明 / 解决办法 |
|------|:--------:|----------------|
| 地址栏显示 **"不安全"** 或无锁标志 | ✅ 正常 | 系统用裸 IP 直连访问（免域名备案，最快上线），功能 100% 不受影响，放心使用 |
| **打开网址没进登录页，直接进了首页**，找不到"游客浏览公开事件"入口 | ✅ 正常 | 说明浏览器**记住了上次的登录状态**（登录态会保留，不会自动过期）。想回到游客视角：点右上角头像 → **"退出登录"** 即可回到登录页；或直接用**无痕/隐私窗口**打开网址，就是干净的游客态。切换 user / admin 账号也用这个方式先退出再登录 |
| **舆情助手回答要等十几秒** | ✅ 正常 | AI 在做多步推理，不是卡死。会先逐字"流式"出字，请稍候；复杂/联网问题更慢属正常 |
| 注册账号时**只能注册普通用户、没有"管理员"选项** | ✅ 正常（安全设计）| 防止任何人自助获取后台权限。审核管理功能请直接用本文档提供的 `admin` 账号登录 |
| 点"AI 预审建议"或对话时提示**"模型暂不可用/请稍后重试"** | ⚠️ 偶发 | 第三方大模型通道偶尔拥堵。**稍等一两分钟重试**即可；系统不会因此崩溃或乱答 |
| 首页顶部写**"数据截至 7/15"**，趋势图却写**"截至 7/19"** | ✅ 正常 | 两个是不同数据：横幅指**已发布事件**的最新日期（要过人工审核会稍晚），趋势图指**帖子**的最新日期。文案已分别标注"事件数据/帖子数据" |
| 发帖趋势图**最后一两天数字很小** | ✅ 正常 | 该图按帖子的**发布日期**统计（反映"哪天讨论多"），不是按采集日期；当天数据自然少 |
| 用普通用户访问后台管理页面 | ✅ 正常拦截 | 会跳转"无权限"页面——这是权限隔离生效，符合预期 |
| **证据采集**页显示"暂无可用检索模型" | ✅ 正常 | 联网检索需要配置密钥，演示环境可能未开；可查看页面上**已有的历史检索记录**了解该功能 |
| 页面数据看起来和上次不一样 | ✅ 正常 | 团队在持续采集真实数据（语料在增长），且管理员在审核发布新事件，内容会更新 |
| 想回到上一个页面 | — | 用浏览器后退键，或点左侧菜单直接跳转；顶部品牌 Logo 可回首页 |

> **总原则**：本系统的设计哲学是**"失败朝安全侧"**——它宁可如实告诉您"暂不可用/暂无数据"，
> 也绝不编造一个看似正确的错误答案。所以您看到的每一条结论都可以信任其来源。

## 6. 如果系统临时无法访问

线上站点依赖云服务器与共享数据库，极小概率遇到网络波动。若打不开或数据异常，请联系团队成员，
我们可在**几分钟内**恢复（服务器支持一键重启，另有本地演示环境作为备份）。这本身也是项目
"运维可靠性"的一部分。
