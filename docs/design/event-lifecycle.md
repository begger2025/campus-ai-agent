# 事件状态研判（生命周期）：悬而未决的事不随时间沉底

> 代码：`backend/agent/public_opinion_core/llm_lifecycle.py`（核心，判断）、
> `backend/agent/public_opinion_core/recency.py`（算术，因子）、
> `backend/services/event_lifecycle.py`（部署，接模型）、
> `backend/routers/api.py::sort_event_rows`（读侧排序，前端真正消费的那个顺序）
> 消融：`scripts/ablation_event_lifecycle.py` -> `docs/event-lifecycle-ablation.md`

## 1. 被修的缺陷

时效衰减（17d5ef2）把排序键变成 `severity_weight(risk_level) × 0.5 ** (age_days / 21)`，
一举把五年前的旧事件从首屏赶了下去。**但它只认年龄**：两个同龄的事件，在它眼里没有区别。

而真实语料里，同龄的事件可以处在完全不同的状态：

| 事件 | 年龄 | 严重性 | 真实状态 |
| --- | ---: | --- | --- |
| 东校区宿舍火情 | 3.5 个月 | high / 95 | 火已扑灭、校方已通报、无人员伤亡、调查已立案 —— **事情结束了** |
| 中大杰青实名举报 | 2.2 个月 | high / 91 | 调查有结论了吗？没有 —— **口子还开着** |
| 中大作息调整争议 | 2.5 个月 | medium / 62 | 校方只说「会关注师生关切」—— **然后呢？** |

火情作为记录仍然严重（严重性是事实，不因时间打折，这一点没变），但**学校已经不需要再为它
做任何动作**；举报和作息争议没有结论，它们仍然是学校要处置的东西——哪怕最后一条帖子是两个月前的。

**「已了结」还是「悬而未决」是对内容的判断，不是时间的函数。**

- **时间戳答不了**：停止发帖既可能是因为事情解决了，也可能是因为没人再关注但问题还在。
- **关键词答不了**：「通报」既出现在"校方已通报处理结果"里，也出现在"至今未见校方通报"里；
  同一个词，相反的状态。这是闭集词表的死穴，和 `llm_risk.py` 里那六个电诈词是同一类问题。
- **读一遍帖子的模型答得了**。

这是时间这根轴上**唯一**该上 LLM 的地方——衰减本身是算术（`0.5 ** (age/21)`，可解释、可复现、
零调用），一个字节都不许 LLM 碰。

## 2. 设计：第四根正交轴

四根轴，各判各的，互不改写：

| 轴 | 字段 | 谁算的 | 答的问题 |
| --- | --- | --- | --- |
| 严重性 | `risk_level` / `risk_score` | LLM（`llm_risk.py`） | 学校要不要立即处置？**不随时间打折** |
| 流行度 | `heat_score` / `heat_rank` | 算术（实测互动量） | 这件事有多火？**不改写** |
| 时效性 | `recency_weight` | 算术（`0.5 ** (age/半衰期)`） | 这件事多新？**只是年龄的函数** |
| **生命周期** | **`lifecycle` / `lifecycle_reason`** | **LLM（`llm_lifecycle.py`）** | **这件事完了没有？** |

    priority_score = severity_weight(risk_level) × recency_weight × lifecycle_weight(lifecycle)

### 四个状态（为什么是这四个）

| 状态 | 含义 | 因子 |
| --- | --- | ---: |
| `escalating`（持续发酵） | 没有结论 **且还在扩大**：新帖仍在增加、蔓延到更多平台、出现联名/集体行动。**必须有正面证据** | ×4 |
| `ongoing`（悬而未决） | 没有结论：校方未回应、只有表态性回应（"会关注"/"已收到材料"）、调查仍在进行 | ×2 |
| `resolved`（已了结） | **有过一件事，且已处置完毕** / 已通报结论 / 已结案。**学校不需要再做新的动作**。严重的事一样可以是 resolved（火灭了、通报发了、立案了） | ×0.5 |
| `not_applicable`（非事件） | **本来就不需要处置**：咨询提问、报考答疑、参观/开放政策询问、攻略与经验分享、校园生活记录。这里**没有一件要学校处置的事**，谈不上结没结 | ×0.5 |
| （未研判） | LLM 关掉 / 超时 / 幻觉 / 老数据 / 库里的脏值 | ×1.0（**恒等**） |

前两者都该抗衰减，但**程度不同**：一个还在涨的舆情比一个冷下来但没结论的事更急；把它们压成
一档，等于承认"我们分不出急和不急"。

**`not_applicable` 是被实测逼出来的第四档**（三状态版在 04f25f5 上线，缺陷当场就暴露了）：
前三档**全都预设了"存在一件待处置的事"**。可语料里「中大图书馆对外开放」「中大参观开放询问」
「中大食堂对外开放」「中大计算机专业咨询」这些帖子是在**提问**（"图书馆对校外开放吗？"），
不是在提诉求——它们没有"待处置的事"，"结没结"这个问题对它们**根本没有意义**。
旧提示词的兜底规则（**「拿不准就选 ongoing」**）把它们全部塞进了「悬而未决」，理由清一色是
"未见校方结论"。于是看板对着一个**提问贴**挂出「悬而未决」徽标——**一句假话**。
而结构完全相同的「中大考研信息汇总」「中大校园与宿舍展示」，同一个模型又判了 `resolved`
（理由"未见待处置问题"）——**同一类内容两种判法，这不是判断，是模型在硬凑三个不合身的选项**。

改判 `resolved` 同样是撒谎：**「已经处置完了」和「本来就不需要处置」是两句不同的话**，
前者说"有过一件事"，后者说"从头到尾就没有要学校做的事"。所以它必须是一个独立的状态。
（再多的档——如 `monitoring`——在这份语料上没有可靠证据支撑，模型只会瞎猜。）

### 兜底规则：为什么把「拿不准就选 ongoing」删掉

旧兜底的本意是"两种错误代价不对称"（漏埋一个还开着的口子 ≫ 多留一个已了结的事几天），
但它是一条**无差别**兜底：一个"不知道该判什么"的模型会**系统性地抬高紧急度**。
上面那四个咨询贴就是它的产物——它们不是被判错的，是**没地方可去**。

新提示词把「拿不准」拆成两种，各自给出**有内容的**指令（而不是一个默认值）：

| 拿不准什么 | 怎么办 | 为什么这是诚实的 |
| --- | --- | --- |
| 拿不准"**是不是**一件要处置的事" | 看帖子在干什么：提问 / 攻略 / 分享 / 介绍 -> `not_applicable` | 这**不是猜**，是分类，答案就在文本里（"图书馆开放吗"是个问句） |
| 确认是一件事，拿不准"**结没结**" | 判 `ongoing` | 这**不是兜底，是定义**：证据里看不到结论，就不许替学校宣布它结束了 |
| 拿不准"是不是**还在扩大**" | 判 `ongoing`，**不许**判 `escalating` | `escalating` 必须有正面证据。**紧急度只能被证据抬高，不能被无知抬高** |

一句话：不确定性不再被兑换成紧急度。

### 因子的量级（为什么是 4 / 2 / 0.5 / 0.5）

**取 2 的幂，因为这样能用半衰期读**，而这是答辩上唯一站得住的解释方式：

    0.5 ** ((age - 21) / 21)  ==  2 × 0.5 ** (age / 21)

- `×2`（ongoing）⇔ 把事件当作**年轻了一个半衰期（21 天）**；
- `×4`（escalating）⇔ 年轻两个半衰期（42 天）；
- `×0.5`（resolved）⇔ 当作**老了一个半衰期**。

于是「悬而未决」有了精确的含义：**它抵得过三周的沉底，不多不少**。

**上界是刻意压住的**：整根轴的动态范围是 8×（0.5 → 4），**小于严重性的 9×**（low → high）。
所以「持续发酵的低风险」永远压不过「已了结的高风险」——生命周期是第四根轴，不是推翻严重性的后门。
（它确实能翻转相邻档：一个持续发酵的 medium 可以压过一个已了结的 high。这是**要的**行为：
火已经灭了、通报也发了，学校不需要再对它做动作；那个还在发酵的争议需要。实测里这正是
「作息调整争议」升到第 3、「宿舍火情」落到第 4 的原因。）

**`not_applicable` 为什么也是 0.5**（而不是 0.25、也不是和 `resolved` 分开）：取值被两个约束
夹死，答案唯一。

1. **必须 < 1.0**：咨询/分享类内容不急、不该抗衰减，更不该和真事件抢版面（缺陷版里它拿的是 ×2）。
2. **必须 >= 4/9 ≈ 0.44**：`not_applicable` 最危险的错法是把一个**真事件**说成"这不是事件"。
   若因子低于 4/9，一个被误判的 high 就会掉到一个 low 的 escalating 之下（9 × f < 1 × 4），
   生命周期就成了**推翻严重性的后门**——而"永远不做后门"正是上面刻意压住动态范围的原因。

2 的幂里同时满足这两条的**只有 0.5**。它和 `resolved` 同值不是偷懒：**对排序而言这两句话是同一句**
（"学校没有待办动作，不必抗衰减"），区别在**理由**——而理由正是徽标和 `lifecycle_reason` 展示的
东西。排序上不多说一个字，展示上不少说一句真话。（"让咨询贴彻底离开首屏"这件事**不该**由生命
周期来办：那是严重性（low = ×1 vs high = ×9）和时效衰减的活儿。真按"压到所有事件之下"去调因子，
换来的就是上面第 2 条那个后门。）

整根轴的动态范围因此**仍是 8×**（0.5 → 4），四档不变。

**「已了结」不等于删除**：3.5 个月的火情打了 0.5 折仍排第 4 / 28 —— severity 95 托着它。

### 降级：未研判 = 恒等，不是"已了结"，也不是"非事件"

`lifecycle=""` -> 因子 **1.0**。这条口径和 `recency_weight` 对未知年龄、`platform_weights` 对
未知平台的口径完全一致：**"不知道结没结" ≠ "已经结了"**，绝不许凭空把一个事件打折沉底。
第四档加进来之后这条口径**一个字没松**：**"不知道是不是事件" ≠ "它不是事件"**——
模型编的状态（`dormant`）、库里的脏值、LLM 挂掉，一律退回**未研判（1.0）**，
**绝不静悄悄变成 `not_applicable`**（那会凭空给它打 5 折）。`not_applicable` 是模型可以**明说**
的一个合法判断，不是任何失败路径的落脚点。

它同时是降级保证的基石：LLM 全挂时公式逐位退化回改造前的 `severity × recency`，
排序不变，而不是变成随机。

### 提示词挡的五种误判（`services/event_lifecycle.py`）

1. **先问"是不是一件要处置的事"，再问"结没结"**：提示词现在是**两问**。第一问答"没有"就是
   `not_applicable`，到此为止。这是修掉「提问贴挂着『悬而未决』」的关键——三档全都预设了
   "有一件事"，那四个咨询贴不是被判错的，是**没地方可去**。
2. **"已处置完毕" ≠ "本来就不需要处置"**：`resolved` 和 `not_applicable` 被明确讲成两句不同的话。
3. **问题不是"多严重"**：严重性已经有 `event_risk.py` 判过了，而严重的事**恰恰可能已经了结**。
4. **状态不是热度**：没人转发不代表事情解决了（火情播报只有 3 个赞，但它确实结束了）。
5. **表态不是结论**：「会关注师生关切」「已收到材料」「正在核实」——都是 `ongoing`。
   这是真实语料里最容易骗过关键词规则的一类句子。

**被删掉的那条**：`~~拿不准就选 ongoing~~`。见上面「兜底规则」一节——不确定性不再被兑换成紧急度。

### 一个诚实的发现：`escalating` 本轮 0 / 28

三状态版里「举报」和「作息」被判成 `escalating`；本轮它们都是 `ongoing`。这是新提示词的
**直接后果**：它把 `escalating` 的门槛写成"**必须有还在扩大的正面证据**"，并明令不许拿它当
"拿不准"的去处。而模型面对的是一份**冻结的 fixture**——它根本看不到"新帖还在不在增加"，
只能从措辞里嗅发酵感。三状态版的报告自己就记着这一点（「这一档的判据比另外两档软」）。

两面都说清楚：
- **方向没错**：改判后的理由（「帖内未见校方结论」「校方仅称会回应关切」）在语料里**字面成立**，
  两个事件照样抗衰减、照样排在第 1 和第 3，排序**零影响**。紧急度只能被证据抬高，不能被无知抬高。
- **但这一档在本语料上未被触发**，它的区分力没得到验证。要把它做硬，得给它一个**算术**判据
  （成员帖"最近 7 天占比"——时间分布是现成的），而不是继续靠模型读语气。
  这次不把没验证过的东西写进代码。

### 另一个如实记下的观察：前 8 名里仍有 3 个「非事件」

「中大火箭试验成功」「中大考研信息汇总」「中大食堂试吃会」——×0.5 已经把它们压到 5 个真事件
**之下**（第 6/7/8），但它们还在首屏。这不是排序判错了，是**语料稀疏**：这份快照里真正的舆情
事件只有 5 个，剩下的位置只能由咨询/分享类内容填。

**不用调权重去掩盖它**：把 `not_applicable` 的因子继续往下压（0.25），代价是一个被误判成
「非事件」的**真事件**会掉到低风险事件之下——那才是生命周期推翻严重性的后门（见 §2 的量级论证）。

  **全部一致** —— 状态只进排序，不改事实，也不改衰减算术。
- LLM 用量：28 次调用、41229 token、127 秒（提示词改了 ⇒ 缓存键变了 ⇒ 这是一批全新的付费调用；
  之后 temperature=0 + JSON 缓存 ⇒ 重复跑 28 次全部命中缓存、0 token）。

## 5. 降级（逐事件，全部有测试）

| 情况 | 行为 |
| --- | --- |
| 未配 key / `EVENT_LIFECYCLE_ENABLED=false` | assessor 为 `None`，跳过研判；所有事件因子 1.0，排序退化回改造前 |
| assessor 抛异常（超时/网络） | **该事件**保持未研判，warning 记进 `agent_run_logs`，其余事件不受影响 |
| 返回 `None` / 不是 JSON 对象 | 同上 |
| 编了一个不在枚举里的状态（`dormant`） | 同上（编造的状态永远不许变成一个排序因子）。**`not_applicable` 是枚举里的合法状态，编造的不是** |
| 给不出理由（空串/不是字符串） | 同上（没有理由的判断在看板上和答辩里都辩护不了） |
| 一个事件都没判成 | `lifecycle_mode` 如实记成 `none`（**不许假装 AI 上过**） |
| 库里的 `lifecycle` 是脏值 | 读侧 `lifecycle_from_payload` 只认**四个**枚举值，其余一律当未研判（1.0）——**不是** `not_applicable`（"不知道是不是事件" ≠ "它不是事件"） |

`backend/tests/test_events_api_lifecycle.py`（GET /api/events 的顺序与 payload，7 例）。
