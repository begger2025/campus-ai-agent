A 臂（无状态，改造前）：`priority = severity_weight(risk_level) × recency_weight`
——衰减只认年龄：一个 3.5 个月前**已经了结**的火情，和一个 2 个月前**仍无结论**的实名举报，
在它眼里只有「谁更新」的差别。

B 臂（生命周期）：`priority = severity × recency × lifecycle_weight(lifecycle)`，
`lifecycle_weight` = {escalating: 4.0，ongoing: 2.0，resolved: 0.5，not_applicable: 0.5，未研判: 1.0}。
因子取 2 的幂，所以能用半衰期读：×2 ⇔ 把事件当作**年轻了一个半衰期**（21 天），×0.5 ⇔ 当作老了一个半衰期。

`not_applicable`（非事件）是这一轮新增的第四档：咨询/攻略/分享类内容**没有待处置的事**，
上一轮被兜底规则「拿不准就选 ongoing」判成了「悬而未决」——本次消融就是来验它修没修好的。

## 诚实记录

**`escalating` 这一档本轮一个都没判出来（0 / 28），而上一轮（三状态版）「中大杰青实名举报」
和「中大作息调整争议」都是 escalating。** 这是新提示词的直接后果：它把 escalating 的门槛
写成「必须有**还在扩大**的正面证据（新帖仍在增加 / 蔓延到更多平台 / 出现联名）」，
并明令**不许**把它当作「拿不准」的去处——紧急度只能被证据抬高，不能被无知抬高。
于是在一份**冻结的 fixture**（模型看不到「新帖还在不在增加」）上，没有事件够得上这一档。

怎么看这件事，如实说两面：
- 上一轮的报告自己就记着，escalating 与 ongoing 的边界当时是由**文本语气**决定的，
  「这一档的判据比另外两档软」。现在模型改判 ongoing，理由是「帖内未见校方结论」
  「校方仅称会回应关切」——这两句话在语料里都**字面成立**，方向也没变（照样抗衰减）。
- 但代价是：这一档在本语料上**未被触发**，它的区分力在这份 fixture 上没有得到验证。
  排序上零影响（见下），可它意味着「急」和「更急」目前实际只有一档在起作用。
  真要把它做硬，得给它一个**算术**判据（成员帖近 7 天占比 —— 时间分布是现成的），
  而不是继续让模型从措辞里嗅发酵感。这次不把没验证过的东西写进代码。

**前 8 名（B 臂）**：中大杰青实名举报、东校区宿舍搬迁、中大作息调整争议、东校区宿舍火情、中大缩短课间争议、中大火箭试验成功、中大考研信息汇总、中大食堂试吃会。
——真事件（举报 / 搬迁 / 作息 / 火情 / 缩短课间）**牢牢占住前 5**，顺序与上一轮逐位一致：
`not_applicable` 换掉 `ongoing` 之后，没有一个真事件被挤下去。

**但前 8 名里仍有 3 个「非事件」**（中大火箭试验成功、中大考研信息汇总、中大食堂试吃会）——
×0.5 把它们压到了 5 个真事件之下，可它们还在首屏。这不是排序判错了，是**语料稀疏**：
这份快照里真正的舆情事件只有 5 个，剩下的位置只能由咨询/分享类内容填。如实记在这里，
不用调权重去掩盖它——把 `not_applicable` 的因子继续往下压，代价是一个被误判成「非事件」
的**真事件**会掉到低风险事件之下（那才是生命周期推翻严重性的后门）。
