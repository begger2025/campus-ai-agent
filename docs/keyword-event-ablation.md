# 消融实验：智能选题 —— 看不看得见「事件」

语料：`data/fixtures/event_clustering_297.json`（297 条 processed_posts 只读快照）
提问：`chat_query_log` 全表快照（**3 行**，其中 2 行无关键词）——线上就这么稀疏，如实用。
参数：now=2026-07-12T00:00:00（注入，可复现） half_life=21.0 天 model=gpt-5.4 temperature=0
**不连数据库。**

## 缺陷

```
grep -c event backend/agent/public_opinion_core/keyword_planner.py \
             backend/services/keyword_suggestion_adapter.py   ->   0 和 0
```

选题器的候选池只有两个来源：**用户问过什么**、**已经爬回来什么**。它从来没听说过「事件」——
于是同一个系统，一边把「中大杰青实名举报」判成 high(91)、悬而未决、全库第一优先级，
一边让选题器继续推荐**「食堂」**。左手不知道右手在干什么。

## 两条腿分别站在原则的哪一侧

| 问题 | 谁来答 | 依据 |
| --- | --- | --- |
| 这个词有多值得爬 | **算术** | demand / gap / heat / `severity×recency×lifecycle` |
| 这件事有多严重、完了没有 | **LLM**（早就判完落库了） | 读帖子 |
| 这件事**该用什么词去搜** | **LLM** | 读帖子——**排序器排不出它没见过的词** |

事件项的分数：`0.3·event_norm × event_penalty × 10`，与老三路（`0.5/0.3/0.2`）**并列相加，不重新归一化**。
理由：归一化会让**一个事件都没有的部署**每个词凭空掉 30% 分——这一路明明什么都没说。
代价是分数上界从 10 变成 13.0，如实记在这里。

管理员点开就知道「学术不端」是从哪件事上长出来的，而不是一个凭空冒出来的词。

## 七、人工闸门没有动

这些**全都只是建议**。`GET /api/admin/keyword-suggestions` 返回它们，管理员点一下才进
爬取队列——**没有任何东西被自动入队**。和证据投递、事件发布同一条纪律：**AI 提议，人来决定**。

## 诚实记录（**不利的也写**）

**1. 「食堂」仍然是第 1 名——而且这是对的。**

缺陷描述里最刺眼的一句是「系统的头号事件是学术不端丑闻，选题器还在推荐食堂」。
改造之后**「食堂」依然排第 1**（8.00 分，一分没变）。这不是没修好，这是权重在按
设计工作：`chat_query_log` 里有一个**真人**问了「食堂」并且只命中 1 条站内数据——
`demand(0.5) + gap(0.3)` 打满 8.00 分。而 `W_EVENT=0.3` 的事件项满分只有 3.00。
**真人敲下的问题 > 系统推断出来的当务之急**——这个排序是我主动选的，不是妥协。
变的是：丑闻的检索词从**根本不存在**变成了第 2-7 名，紧跟在食堂后面。

**2. 提问语料只有 3 行（2 行还没有关键词）。**

demand/gap 两路几乎是空的。这既解释了「现行臂只推荐食堂」，也意味着
**本次消融放大了事件臂的优势**：一个有几千条真实提问的系统里，`W_ASK=0.5` 会
更经常压过 `W_EVENT=0.3`，事件词不会像这里一样一口气霸占 6 个席位。如实说明。

**3. 卫生规则在真实数据上一次都没触发（0 / 25 个词被拒）。**

模型这一轮**没有提出任何一个该被拒的词**——没有「校园生活」，没有超过 12 字的句子，
没有一个词带「中山大学」前缀。这是好事，但它也意味着**这份报告没有在真实数据上
演示过降级路径**。拒绝逻辑的证据在注入式单测里（`test_llm_keywords.py::HygieneTest`：
模型提「校园生活」「中山大学」「日常」-> 被 planner 自己的 `GENERIC_BLACKLIST` 拒掉，
全被拒时该事件不贡献任何词并记 warning）。**没在语料上触发 ≠ 没人见过它工作**，
但也**不能**拿这份报告去声称「卫生规则拦下了模型的胡话」——这一轮它没有胡话可拦。

**4. 「耿同学」是一个自然人的名字。**

模型把举报人的网名提成了检索词。作为**检索策略**它是对的（真人就是这么搜的），
但把一个**具体个人**的名字放进爬取队列是另一回事。系统**没有**自动入队它——
它和别的词一样躺在建议列表里等管理员点。**这正是人工闸门存在的理由**：
模型可以提议，但「要不要围绕一个自然人做定向采集」不该由模型决定。

**5. 近义词冗余：「东校区宿舍搬迁」「东校宿舍搬迁」「同校区搬迁」「宿舍搬迁」四个词并列 1.73。**

planner 的合并规则（短词并入**唯一**包含它的长词）在这里失效了：「宿舍搬迁」同时被
「东校宿舍搬迁」和「东校区宿舍搬迁」包含 -> 视为歧义 -> 不合并。于是同一件事占了 4 个席位。
**这是本次改造引入的新问题**（事件臂把同义说法一起灌了进来），没有修，如实记：
代价是 Top-N 里的位置被浪费，而不是推荐错。管理员看得出它们是一回事。
