## 划分后

| 页面 | = 数据层 × 动词 | 回答的问题 | 独占什么 |
|---|---|---|---|
| **首页** | 概览层 × 看 | 今天怎么样？ | 全局数字 + 7 天趋势 + 最新动态 |
| **舆情分析** | **帖子层** × 统计 | 395 条数据在说什么？ | 情绪分布 / 平台分布 / 发帖趋势 / 热度榜 |
| **事件列表** | **事件层** × 检索 | 找到某个事件 | 多维筛选 / 排序 / 分页 |
| **舆情工作台** | **单事件** × 研判 | 这件事到底怎么回事？ | AI 研判的全部"凭什么" |
| **舆情关注** | **中高风险** × 处置 | 我要跟进什么？ | 影响评估 |
| **舆情助手** | 全部 × 对话 | 任何问题 | ReAct 多步推理、三层检索 |

**本轮已执行**：舆情分析页移除事件列表（那是事件层的东西，属于另外三个页），改为帖子层的
统计分析（`GET /api/sentiment/stats`）。四张统计卡也从"1 张帖子层 + 3 张事件层"改成**全部帖子层**。

**尚未执行**（下一轮）：工作台补齐 AI 研判证据、事件列表去掉与工作台重复的预览、
舆情关注去掉与首页重复的统计卡。

# 数据的两层，两种门

这一节回答的是另一个真问题：**"普通用户为什么能看到所有帖子？不是要管理员审核完才能放出来吗？"**

| | 帖子（processed_posts，395 条） | 事件（public_events，105 条） |
|---|---|---|
| 它是什么 | **公开网络内容的搬运**（微博/知乎/小红书上人人可见） | **AI 的结论**（LLM 研判的风险等级、生命周期） |
| 需要什么门 | **登录门**（内部原始数据，不给未登录的人 curl 走全库） | **人工审核门**（AI 会错，必须人点了才能发布） |
| 门在哪 | `/api/posts`、`/api/sentiment/posts` 要 `get_current_user` | 后端强制 `status == 'published'`——105 个里只有 **10 个**可见（62 archived + 33 draft 一个都出不来） |
| 审过之后 | 仍只对登录用户可见 | **对游客公开**（事件列表/详情是公开页） |

一句话：**人工闸门守住的是 AI 的结论，不是公开数据的搬运。**

改造前 `/api/posts`、`/api/sentiment/posts` **完全没有认证依赖**——前端 router 里标的
`roles: ['user','admin']` 只是前端的门，后端不设防，不登录直接 `curl` 就能拿走全库。已修。

# 数据质量：过滤器只管新爬取，存量要回溯清

2026-07-14 在库里发现两条与中山大学无关的帖子：

| 帖子 | 平台 | 爬取时间 | 为什么漏进来 |
|---|---|---|---|
| 床垫集采招标广告 | weibo | 2026-07-11 02:51 | 拦它的词（`集采`/`招标方`）**是 7-11 那天才加进 `TOPIC_NEGATIVE_TERMS` 的**——它正是当时发现问题的那条样本。过滤器补上了，**存量数据从没清过** |
| 台湾国立中山大学选课 | zhihu | 2026-07-11 01:08 | `TOPIC_RELEVANCE_TERMS` 含「中山大学」，而"台湾国立**中山大学**"含这个子串 → 放行。**同名不同校**，词表天生分不开 |

**两条教训**：

1. **过滤器只管新爬取**。加了词表不等于库干净了——存量要靠 `scripts/purge_offtopic_posts.py`
   回溯清（干跑预览 → 人工确认 → 执行 → 幂等复跑，删前自动备份）。
2. **词表分不开同名实体**。证据采集那边靠**域名白名单**正确挡住了 `nsysu.edu.tw`（台湾中山大学），
   爬虫侧只有词表，挡不住。这是已知局限，答辩如实说明。

已清理：`processed_posts` 397 → **395**，已发布事件不受影响（这两条不是任何事件的代表帖）。
