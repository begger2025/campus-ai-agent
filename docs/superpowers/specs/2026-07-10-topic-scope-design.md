# 设计：爬取内容主题限定（中山大学校园舆情）

- 日期：2026-07-10
- 状态：已批准推进（用户需求："爬取的主要内容限制在中山大学主题下，不要爬取其它无关的内容"）
- 范围：仅 MediaCrawler；主项目零改动（面板复制的裸关键词经查询侧限定自动获得主题约束）

## 1. 问题

爬取按关键词全网搜索："宿舍空调"会返回任何高校的内容；"中山大学 食堂"也会因平台模糊
匹配混入中山市美食、其他高校帖子。无关内容既浪费小红书每轮 5 条的详情额度，又污染
processed_posts 语料与推荐信号。

## 2. 双层方案

**第一层：查询侧限定（三平台）**
- 配置 `CRAWL_TOPIC_QUALIFIER = "中山大学"`（空 = 不启用）。
- 每个搜索关键词组装为 `f"{qualifier} {keyword}"`；关键词已含任一主题相关词
  （见词表）时不重复附加（大小写不敏感）。存量配置如 "中山大学宿舍搬迁" 不受影响。
- `source_keyword` 记录组装后的词；主项目 planner 的 normalize 会剥校名前缀，
  推荐/降权匹配口径不受影响（已核对）。

**第二层：结果侧词表过滤**
- 配置 `TOPIC_RELEVANCE_TERMS = ["中山大学", "中大", "sysu", "逸仙", "康乐园",
  "双鸭山", "南校园", "东校园", "北校园", "珠海校区", "深圳校区"]`（可调；刻意不含
  "大学城"这类多校共用词）与 `ENABLE_TOPIC_RELEVANCE_FILTER = True`。
- 过滤位置按"该平台哪里文本最全"选择，避免误杀：
  | 平台 | 过滤点 | 判定文本 |
  |---|---|---|
  | 微博 | 搜索循环内、**长文展开之后**、入库/收集评论 id 之前 | mblog 全文 |
  | 贴吧 | notes_list 入库前（与时间窗口过滤同点） | title + desc |
  | 小红书 | **详情获取后、入库前**（搜索卡片常只有标题，标题级过滤会误杀标题不带校名的相关帖） | 标题 + 正文 + 标签名 |
- 判定：任一文本命中任一词表项即相关；全部未命中则丢弃并计数打日志。
  词表为空时不过滤（等价关闭）。

## 3. 实现

- 新纯函数模块 `tools/topic_scope.py`（pytest）：
  `compose_topic_keyword(keyword, qualifier, relevance_terms) -> str`、
  `matches_topic(texts: Iterable[str|None], relevance_terms) -> bool`（大小写不敏感，
  terms 为空返回 True）。
- 三平台 core 接线（查询组装 + 各自过滤点），xhs 被过滤的详情同时跳过图片下载/
  增强 JSON 导出/评论抓取。
- 已知代价：小红书的结果侧过滤发生在详情之后，无关帖仍消耗详情额度——但查询侧
  限定已把无关比例压到很低，且这样保证零误杀；答辩口径如实说明。

## 4. 测试与验收

`tests/test_topic_scope.py`（pytest，约 10 个）：组装（附加/已含跳过/空限定词直通/
大小写）、判定（命中任一文本、latin 大小写、无命中、空词表全保留、None/空文本容错）。
基线不变：43+新增 通过 + 1 个既有失败（test_store_factory excel）。三平台接线靠审查 +
用户真实爬取冒烟。
